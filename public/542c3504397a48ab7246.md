# はじめに

Qiitaの記事はブラウザから直接書くこともできますが、**GitHubで管理すると次のメリットがあります。**

- GitHubで履歴管理できる
- バックアップになる
- チームレビューができる
- pushするだけでQiitaに自動投稿できる

今回は **GitHub Desktopを使って、ターミナルなしで管理〜自動投稿まで** を1記事で完結させます。

---

# 1. GitHubでリポジトリを作成

まず、Qiita記事を管理するための **GitHubリポジトリ** を作成します。

![my-Qiita.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/4257135/decc3b43-c1c3-4581-bb12-0d1ef84fbc54.png)

設定は次のようにします。

| 項目 | 日本語 | 設定 |
|---|---|---|
| Repository name | リポジトリー名 | my-qiita |
| Description | 説明 | Source repository for my Qiita articles |
| Visibility | 公開・非公開 | Public |
| Add README | README追加 | Off |
| Add .gitignore | .gitignoreの追加 | None |
| License | ライセンス | None |

設定が完了したら **Create repository** をクリックします。

```
my-qiita
├── _template.md   ← publicの外に置く
└── public
    └── first-post.md
```

# 5. Qiita CLIをセットアップする

GitHubからQiitaへ自動投稿するために、**Qiita CLI** を使います。

### 5-1. Qiitaのアクセストークンを取得

1. Qiitaにログインし、右上のアイコン → **設定** を開く
2. **アプリケーション** → **個人用アクセストークン** → **新しいトークンを発行する**
3. スコープは `read_qiita` と `write_qiita` にチェック
4. 発行されたトークンをコピーしておく（再表示されないので注意）

![token-crate.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/4257135/bfcc8842-f86c-48fb-b130-e12e80820af9.png)

![token-copy.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/4257135/22b98bc5-a71f-442d-952c-b0068a8db97e.png)

### 5-2. GitHubにシークレットを登録

1. GitHubの **my-qiita** リポジトリを開く
2. **Settings** → **Secrets and variables** → **Actions** → **New repository secret**
3. 以下を入力して **Add secret**

| 項目 | 値 |
|---|---|
| Name | `QIITA_TOKEN` |
| Secret | 先ほどコピーしたトークン |

![token-github.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/4257135/6016f792-5292-4e09-90e2-b35d2fac2e58.png)

# 6. GitHub Actionsで自動投稿を設定する

### 6-1. ワークフローファイルを作成

VS Codeで以下のフォルダ・ファイルを作成します。

```
my-qiita
├── .github
│   └── workflows
│       └── publish.yml
└── public
    └── first-post.md
```

### 6-2. publish.yml の中身
![publish-yml.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/4257135/6516c817-3a53-47d5-b540-e3b585fbfde1.png)
```yaml
name: Publish to Qiita

on:
  push:
    branches:
      - main
    paths:
      - "public/**"
  workflow_dispatch:

permissions:
  contents: write

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: false

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7

      # Qiita公式アクション: 投稿後に採番された id / updated_at を自動でコミットし直す
      - uses: increments/qiita-cli/actions/publish@v1
        with:
          qiita-token: ${{ secrets.QIITA_TOKEN }}
          root: "."
```

このワークフローは **`public/` 配下のファイルが変更されてmainにpushされたとき** に自動で実行されます。`workflow_dispatch` を入れておくと、GitHubの **Actions** タブから手動実行もできます。

### 6-3. ワークフローのポイント

| 設定 | 内容 |
| --- | --- |
| `actions/checkout@v7` | リポジトリの中身を取得する |
| `increments/qiita-cli/actions/publish@v1` | Qiita公式アクション。Node.jsのセットアップ、Qiita CLIのインストール、投稿までまとめて行う |
| `permissions: contents: write` | 公式アクションが記事の `id` をリポジトリに書き戻すために必要 |

:::note warn
**重複投稿に注意:** `qiita publish --all` を直接実行するだけのワークフローでは、投稿後に採番された記事の `id` がGitHub側のファイルに書き戻されません。その状態で記事を修正してpushすると、**同じ記事がもう1本新規投稿されてしまいます**。公式アクションは `id` と `updated_at` を自動でコミットし直してくれるので、この問題が起きません。
:::

:::note info
公式アクションがコミットを追加するので、次に作業するときは GitHub Desktop で先に **Fetch origin → Pull origin** をしてから書き始めましょう。
:::


GitHub Desktopに変更が表示されたら：

1. 左下の **Summary** にコミットメッセージを入力
2. **Commit to main** をクリック
3. 右上の **Push origin** をクリック

![commit.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/4257135/f7b67f48-500a-47a6-8d22-aabe42142b61.png)

pushが完了すると GitHub Actions が自動で起動し、Qiitaに記事が投稿されます。

GitHubのリポジトリページの **Actions** タブで「Publish to Qiita」が緑色✅になれば成功です。Qiitaの自分のページを開いて、記事が反映されていることを確認してください。

2回目以降は、**記事を書く → コミット → push** だけです。

# うまくいかないときは

| 症状 | 原因と対処 |
| --- | --- |
| Actionsが起動しない | `public/` 以外の場所だけを変更した（`paths` で対象外になる）。記事は必ず `public/` 内に置く |
| `401 Unauthorized` | トークンの間違い or スコープ不足。`read_qiita` + `write_qiita` で再発行してSecretsを更新 |
| Node.js 20に関する警告やエラーが出る | `actions/checkout@v4` や Node.js 20 を指定した古い書き方になっている。本記事のymlに置き換える |
| 同じ記事が重複して投稿された | `id` がファイルに書き戻されていない、または `id` を消してpushした。公式アクションを使い、既存記事の `id` は消さない |
| 公式アクションのコミットが失敗する | `permissions: contents: write` が抜けている |
| テンプレートが記事として投稿された | `_template.md` が `public` 内にある。`public` の外へ移動する |
| pushが拒否される（rejected） | 公式アクションのコミットをまだ取り込んでいない。GitHub Desktopで **Pull origin** してから再度push |

# まとめ

今回は **ターミナルをほぼ使わずに** Qiitaの記事をGitHubで管理し、自動投稿するまでの方法を1記事で完結させました。

手順は次の通りです。

1. GitHubでリポジトリを作成
2. GitHub Desktopでクローン
3. publicフォルダを作成
4. Markdownで記事を書く
5. QiitaのトークンをGitHubシークレットに登録

この方法を使うことで

- Markdownで記事を書ける
