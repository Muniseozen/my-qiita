# はじめに

「デザインもAIで生成できる時代、デザイナーはどうAIと付き合うべきか」——この問いに対する私の現時点の答えは、タイトルのとおりです。

**デザインはAIに任せない。でも、Figmaの「整理」は手伝ってもらう。**

私はUI/UXデザインとフロントエンド開発の両方をやってきました。AIは開発でもデザインでも毎日使っています。それでも「デザインそのもの」は任せない。この記事では、その線引きの理由と、実際にAIに手伝わせている整理作業を紹介します。

# 線引きの基準:「正解を決める仕事」か「ルールに従う作業」か

私の線引きはシンプルです。

| | 性質 | 担当 |
| --- | --- | --- |
| デザイン | **正解を決める**仕事(何が「らしい」か、何を優先するかの判断) | 人間 |
| 整理 | **決まったルールに従う**作業(命名規則、スタイル統一、棚卸し) | AI+人間のチェック |

デザインには正解がありません。クライアントの意図、ブランドの「らしさ」、ユーザーへの優先順位——これらは判断であって、計算ではない。「なぜこのデザインなのか」をクライアントに説明する責任も含めて、ここは人間の仕事です。「AIがこう作ったので」とは言えません。

一方、整理には正解があります。「命名規則はこれ」「色はこのトークンだけ」と**ルールさえ決めれば、あとは従うだけの作業**です。そして「ルールに従う作業」は、AIが人間より速く、文句も言わずにやってくれる領域です。

つまり:**ルールを決めるのが人間の仕事、ルールに従うのがAIの仕事。**

## 補足:デザイン案を出させるのはアリ。ただし「参考」まで

誤解のないように書いておくと、AIにデザイン案を出させること自体は否定していません。方向性に迷ったときに案を出させると、自分になかった切り口が見つかることもあります。

ただし、扱いは**参考レベルまで**と決めています。

- AIの案は「発想を広げる材料」。気になる方向があっても、**そこから自分の手でデザインし直す**
- クライアントの意図やブランドに合わせて組み直す工程は飛ばさない
- AIの案を「そのまま採用して仕上げる」ことはしない

距離感としては、「後輩が持ってきたラフ案」くらい。参考にはするけれど、最終的に責任を持つのは自分のデザイン——ここが崩れなければ、案出しはむしろ積極的に使っていい領域だと思っています。

# AIに手伝わせているFigma整理

具体的に何を任せているか(任せられるか)を紹介します。

## 1. レイヤー・フレームの命名

Figmaあるあるの `Frame 427` 問題。命名規則(例:セクションは英語PascalCase、アイコンは `Icon` プレフィックス)を決めて、AIにリネーム案を出させます。

```
この画面のレイヤー構造を見て、命名規則に沿ったリネーム案を一覧で出して。
規則:コンポーネントはPascalCase、画面はScreen〜、アイコンはIcon〜
```

ゼロから名前を考えるのではなく、**出てきた案を人間が承認する**流れにすると、1画面数分で終わります。

## 2. 色・テキストスタイルの「揺れ」検出

`#333333` と `#2F2F2F` が混在している、フォントサイズが13/14/15pxでバラついている——こういう揺れの検出は、人間が目視でやると見落とすうえに苦痛な作業です。ファイル内で使われている色・テキスト設定を洗い出させて、「統一候補」をリストアップさせます。どれに寄せるかの判断だけ人間がやる。

## 3. コンポーネントの棚卸し

ファイルが育ってくると、「微妙に違うボタンが5種類ある」状態になりがちです。似た要素を洗い出させて、「これは統合できそう」「これは意図的な差?」の一覧を作らせます。統合するかどうかの判断は人間。

## 4. デザインの仕様書化・ドキュメント化

コンポーネント一覧、カラーパレット表、余白ルールのドキュメント——**作るのは面倒だけど、あると実装者に喜ばれる**系の文書です。整理が終わったFigmaから書き出させれば、スタイルガイドのドラフトが一瞬でできます。

# この整理、実は「AIのため」でもある

整理をAIに手伝わせることには、隠れたリターンがあります。

いまはFigmaのデザインをAIが読んでコードを生成する時代です(Figma MCP)。AIはレイヤー名・オートレイアウト・スタイルを**構造化データとして**読むので、**整理されたFigmaからは良いコードが出て、散らかったFigmaからは散らかったコードが出ます**。

つまりこういう好循環が作れます。

```
AIに整理を手伝わせる → Figmaが構造化される
→ AIのコード生成の精度が上がる → 人間は判断と仕上げに集中できる
```

整理という「AIに任せられる作業」が、デザイン→実装の全工程でAIの精度を底上げしてくれる。**整理はもはや掃除ではなく、インフラ投資**です。

# おわりに

AIとの付き合い方について、私はどの仕事でも同じルールで運用しています。

- コードなら:AIに書かせてもいい。ただし**自分で説明できないコードは出さない**
- 記事なら:AIと書いてもいい。ただし**核になる経験は自分のもの**
- デザインなら:整理は任せる。ただし、**「らしさ」の判断と説明責任は渡さない**

全部同じことを言っています。**正解を決めるのは人間、決まったことを速くやるのがAI。** この線引きさえ守れば、AIはデザイナーの敵ではなく、一番文句を言わない優秀なアシスタントです。
